# План реализации — базовая версия «Яйцо в Храме»

## Назначение

Этот документ — последовательный набор задач для AI-разработчиков. Он основан на [Game Design Document](game-design-document.md) и [Tech Stack](tech-stack.md).

Цель плана: создать одну законченную локальную браузерную игру для двух людей за одной клавиатурой. В игре есть один храмовый уровень, два персонажа, физическое яйцо, шипы, цветные кнопки, дверь, рычаг, подъёмник, контрольная точка, гнездо и короткая сцена вылупления.

## Что входит в этот план

- Локальный кооператив: два игрока в одном браузере и на одной клавиатуре.
- Один завершённый уровень «Зелёный храм».
- Low-poly 3D-визуал с сине-фиолетовой неоновой палитрой.
- Базовая физика, урон яйца, перезапуск и финиш.
- Один птенец в локальной коллекции после успешного финиша.

## Что намеренно не входит

- Онлайн-комнаты, Colyseus-сервер, приглашения и переподключение.
- Аккаунты, база данных, облачные сохранения и рейтинг.
- Несколько уровней, редактор уровней, достижения и магазин.
- Мобильное управление, геймпады и голосовой чат.
- Сложная постобработка, расширенные визуальные эффекты и полная оптимизация для слабых устройств.

## Правила выполнения

- Выполнять шаги строго по порядку: следующий шаг начинается только после прохождения теста предыдущего.
- Не добавлять функции, которых нет в текущем шаге.
- После каждого шага вручную выполнить указанный тест в браузере и записать результат в рабочем журнале проекта.
- Если тест не проходит, исправить только причину сбоя и повторить тест; не переходить к следующему шагу.
- Для физики использовать фиксированный шаг симуляции 60 раз в секунду. Отрисовка может работать с другой частотой.

## Утверждённые стартовые параметры

Использовать следующие значения для первого играбельного блокинга. Единица движка равна одному метру; стандартный рост персонажа — около 1,5 единицы. Эти значения можно менять только после задокументированного плейтеста.

| Параметр | Стартовое значение |
|---|---:|
| Масса игрока | 1,0 |
| Масса яйца | 4,5 |
| Скорость игрока | 7,0 ед/с |
| Высота прыжка | 2,75 ед. |
| Замедление игрока | 45,0 ед/с² |
| Сила толчка одним игроком | 18,0 |
| Сила толчка двумя игроками | 36,0 (сумма двух толчков) |
| Трение качения яйца | 0,25 |
| Максимальная скорость яйца | 14,0 ед/с |
| Урон от шипов | 100% |
| Урон от сильного удара | 25%, если скорость удара выше 7,0 ед/с |
| Задержка закрытия двери после отпускания кнопки | 0,5 с |

## Этап 1. Основа проекта

### 1. Создать чистый проект

Создать новый проект Vite с шаблоном Vanilla TypeScript. Не подключать React, Vue и другие UI-фреймворки. Создать отдельные папки для игровых модулей, сущностей, рендера, UI, уровней и ассетов согласно `tech-stack.md`.

**Тест:** запустить локальный сервер разработки. В браузере должна открываться пустая страница проекта без ошибок в консоли.

### 2. Подключить обязательные зависимости

Добавить Three.js для рендера и Rapier для физики. Добавить инструменты TypeScript, ESLint, Prettier и Vitest как инструменты разработки. Зафиксировать версии зависимостей в lock-файле.

**Тест:** установить зависимости с нуля и выполнить production-сборку. Сборка должна завершиться без предупреждений об отсутствующих пакетах.

### 3. Настроить проверку качества

Настроить проверку типов, линтер и форматирование. Добавить одну безошибочную тестовую проверку Vitest, чтобы убедиться, что тестовый раннер запускается.

**Тест:** отдельно запустить проверку типов, линтер и тесты. Все три команды должны завершиться успешно.

### 4. Создать игровой запуск и остановку

Создать центральный объект игры, который запускает рендер, физику, ввод и UI. Добавить корректную остановку игрового цикла при закрытии или перезагрузке страницы, чтобы не оставались активные обработчики клавиатуры.

**Тест:** открыть игру, перезагрузить страницу пять раз и проверить консоль. Не должно быть ошибок, дублирующихся обработчиков или ускорения игрового цикла.

### 5. Добавить экран загрузки

Сделать простой DOM-экран с названием игры и индикатором «Загрузка». Экран должен быть виден до полной инициализации рендера и физики, затем плавно исчезать.

**Тест:** открыть страницу с отключённым кешем в браузере. Экран загрузки появляется один раз и исчезает после появления игровой сцены.

## Этап 2. Сцена и визуальная база

### 6. Создать Three.js-сцену

Создать canvas, сцену, камеру, рендерер и цикл рендера. Использовать перспективную камеру с малым углом обзора, чтобы игра воспринималась как платформер с боковым видом, но сохраняла объём low-poly мира.

**Тест:** на странице отображается один цветной куб на тёмном фоне. При изменении размера окна canvas заполняет доступную область без растяжения изображения.

### 7. Создать базовое освещение

Добавить мягкий общий свет, холодный сине-фиолетовый направленный свет и контровой розовый свет. Не добавлять bloom или другие постэффекты на этом этапе.

**Тест:** куб из предыдущего шага имеет различимые освещённую и затемнённую стороны; его грани не выглядят полностью чёрными или полностью белыми.

### 8. Добавить фон ночного неба

Создать статичный low-poly задний план: фиолетово-розовый градиент неба, редкие звёзды, силуэты угловатых гор и крупный светящийся диск солнца у горизонта. Фон не должен иметь коллизий.

**Тест:** запустить игру и убедиться, что фон виден за сценой, не перекрывает платформы и сохраняет композицию при перемещении камеры.

### 9. Создать стили материалов

Подготовить переиспользуемые low-poly материалы для камня, дерева, мха, металла, шипов, яйца, красных объектов и синих объектов. Основная палитра должна быть синей и фиолетовой; красный разрешён только как функциональный акцент.

**Тест:** вывести на тестовой сцене по одному объекту каждого материала. Цвета объектов легко различаются, а красный не доминирует над сине-фиолетовой палитрой.

### 10. Добавить игровую камеру

Камера должна плавно следовать за яйцом по горизонтали и вертикали. Ограничить камеру границами уровня, чтобы она не показывала пустоту за декорациями.

**Тест:** вручную переместить тестовое яйцо к каждой границе уровня. Камера следует за ним, но не выходит за установленные границы.

## Этап 3. Физическая основа

### 11. Создать мир Rapier

Инициализировать физический мир с гравитацией вниз и фиксированным шагом 1/60 секунды. Отделить физическое обновление от отрисовки.

**Тест:** добавить тестовый физический куб над неподвижной плоскостью. Куб должен падать и стабильно останавливаться на плоскости при 30, 60 и 120 FPS рендера.

### 12. Связать физику и визуальные модели

Сделать единый механизм синхронизации: позиция и поворот тел Rapier копируются в соответствующие Three.js-модели после каждого физического шага. Рендер не должен менять физические координаты напрямую.

**Тест:** падение тестового куба в физике визуально совпадает с его 3D-моделью, без заметного отставания или дрожания.

### 13. Создать статичную платформу

Собрать первую каменную платформу из low-poly модели и неподвижного коллайдера. Верх платформы должен быть ровным и пригодным для персонажей и яйца.

**Тест:** физический куб и будущая заготовка яйца остаются на платформе минимум 30 секунд без проваливания и без смещения.

### 14. Создать наклонную платформу

Добавить каменную наклонную поверхность с корректным коллайдером. Она должна позволять яйцу катиться вниз под действием гравитации.

**Тест:** поместить сферу на вершину наклона. Она плавно скатывается вниз и останавливается на ровной площадке внизу.

### 15. Настроить слои коллизий

Выделить слои для игроков, яйца, твёрдых платформ, опасностей и сенсоров. Убедиться, что сенсоры фиксируют пересечение, но не блокируют движение.

**Тест:** тестовый объект проходит через сенсор, но не через твёрдую стену; в журнале появляется только одно событие входа в сенсор на одно пересечение.

## Этап 4. Ввод и персонажи

### 16. Реализовать InputManager

Создать централизованный модуль ввода. Он должен хранить состояния нажатых и отпущенных клавиш, а также кратковременное нажатие для прыжка и взаимодействия. Запретить прокрутку страницы клавишами игры.

**Тест:** в тестовом режиме отобразить текущее состояние действий на экране. Нажатие и отпускание каждой игровой клавиши меняет только соответствующее действие; страница не прокручивается.

### 17. Настроить схему управления Красного

Назначить Красному игроку: `A` и `D` — движение, `W` — прыжок, `S` — присесть или спуск через одностороннюю платформу, `E` — всё взаимодействие, толкание и торможение яйца.

**Тест:** отобразить на экране имя действия Красного. Каждая из пяти клавиш вызывает ожидаемое действие и не влияет на Синего.

### 18. Настроить схему управления Синего

Назначить Синему игроку: стрелки влево/вправо — движение, стрелка вверх — прыжок, стрелка вниз — присесть или спуск через одностороннюю платформу, `Shift` — всё взаимодействие, толкание и торможение яйца.

**Тест:** отобразить на экране имя действия Синего. Каждая из пяти клавиш вызывает ожидаемое действие и не влияет на Красного.

### 19. Создать тело Красного игрока

Создать low-poly персонажа Красного в шлеме с красным костюмом, физическое тело и контроллер передвижения. Он должен двигаться влево и вправо, стоять на платформах и не переворачиваться от столкновений.

**Тест:** Красный проходит по ровной платформе, упирается в стену, не проходит сквозь неё и остаётся вертикальным после столкновения.

### 20. Добавить прыжок Красному

Разрешить прыжок только когда Красный стоит на твёрдой поверхности. Ограничить высоту прыжка так, чтобы он мог забираться на невысокие ступени, но не перепрыгивал задуманные стены.

**Тест:** при удерживании `W` в воздухе второй прыжок не срабатывает; после приземления один новый прыжок снова доступен.

### 21. Создать тело Синего игрока

Создать low-poly персонажа Синего в шлеме с синим костюмом, используя те же физические размеры и возможности, что у Красного.

**Тест:** Синий проходит тот же маршрут, что и Красный, с одинаковой скоростью и высотой прыжка. Игроки могут стоять рядом без проваливания друг в друга.

### 22. Добавить базовую анимацию персонажей

Добавить простые состояния визуала: покой, бег, прыжок и толкание. На MVP допустимы процедурные low-poly анимации без сложного скелета.

**Тест:** при смене каждого движения персонаж переключается на верное состояние, анимация не продолжается после остановки и не влияет на физические размеры тела.

## Этап 5. Яйцо и совместное толкание

### 23. Создать яйцо

Создать крупную белую low-poly модель яйца и динамическое физическое тело овальной формы. Яйцо должно быть почти высотой с персонажа и иметь заметные тонкие трещины.

**Тест:** яйцо падает на ровную платформу, не проходит через неё, слегка перекатывается при толчке и остаётся визуально целым.

### 24. Настроить массу и трение яйца

Установить массу игрока 1,0, массу яйца 4,5 и трение качения яйца 0,25. Один игрок толкает яйцо силой 18,0, два игрока — суммарной силой 36,0. Яйцо должно ощущаться тяжёлым, но преодолевать небольшие подъёмы при совместном толкании.

**Тест:** замерить перемещение на ровной площадке за 3 секунды. При толкании вдвоём яйцо проходит большее расстояние, чем при толкании одним игроком; без игроков оно останавливается.

### 25. Добавить действие «толкать яйцо»

Когда персонаж находится рядом с яйцом и удерживает свою клавишу действия, прикладывать силу в сторону его движения. Не разрешать тянуть яйцо, толкать его издалека или взаимодействовать с ним сверху.

**Тест:** один игрок толкает яйцо только при близком контакте и удерживании действия. Отпускание клавиши или отход от яйца немедленно прекращает толкание.

### 26. Добавить торможение яйцом с противоположной стороны

Если игрок стоит перед катящимся яйцом и удерживает действие, он должен замедлять его без отскока и без прохождения модели сквозь яйцо.

**Тест:** запустить яйцо с наклонной платформы на игрока. Игрок на нижней стороне замедляет яйцо и удерживает его до полной остановки.

### 27. Ограничить опасную скорость яйца

Добавить программное ограничение максимальной скорости яйца в 14,0 ед/с на обычных поверхностях. Оно не должно застревать, но также не должно за один кадр пролетать через тонкие препятствия.

**Тест:** многократно толкнуть яйцо двумя игроками на длинной наклонной площадке. Оно не проходит через стену или шипы в конце маршрута.

### 28. Добавить видимые повреждения яйца

Создать три визуальных состояния: целое, потрескавшееся и критически потрескавшееся. Переход состояния зависит от процента прочности, а не от числа столкновений.

**Тест:** искусственно установить прочность на 100%, 60% и 20%. Для каждого значения отображается соответствующий набор трещин, без изменения размера яйца.

## Этап 6. Опасности, урон и перезапуск

### 29. Создать полосу шипов

Разместить на нижнем уровне крупные металлические low-poly шипы с твёрдой визуальной частью и отдельным сенсором опасности. Шипы должны сразу хорошо читаться на тёмном фоне.

**Тест:** персонаж может стоять рядом со шипами; вход яйца в сенсор шипов фиксируется один раз и не позволяет яйцу пройти через всю полосу за один кадр.

### 30. Реализовать урон от шипов

При касании шипов яйцо получает 100% урона и сразу разбивается. Не применять к этому событию накопление, задержку или защитный период.

**Тест:** столкнуть яйцо со шипами при 100% прочности. Прочность сразу становится 0%, запускается сцена разрушения и уровень не может быть завершён.

### 31. Реализовать урон от жёсткого падения

При столкновении яйца со стеной, полом или препятствием со скоростью удара выше 7,0 ед/с уменьшать прочность на 25%. Лёгкие касания и удары с меньшей скоростью должны быть безопасны.

**Тест:** вызвать удар со скоростью 6,9 ед/с и со скоростью 7,1 ед/с. Первый не наносит урон, второй уменьшает прочность ровно на 25%.

### 32. Создать HUD прочности

Добавить в верхней части экрана DOM-индикатор «Прочность яйца» со значением в процентах и цветовым переходом от безопасного к критическому состоянию.

**Тест:** изменить прочность яйца на 100%, 50% и 10%. Число и заполнение полосы совпадают с фактическим состоянием яйца.

### 33. Реализовать разрушение яйца

При достижении 0% прочности остановить управление, показать краткую сцену разрушения и предложение вернуться к последней контрольной точке. Не показывать сцену успеха.

**Тест:** установить прочность яйца на 1%, затем вызвать урон. Игра блокирует управление, показывает разрушение и после выбора перезапуска не оставляет старое разбитое яйцо на уровне.

### 34. Добавить опасную нижнюю зону

Создать невидимый сенсор под уровнем. Если туда падает яйцо, Красный или Синий, немедленно запускать перезапуск с последней контрольной точки.

**Тест:** отдельно столкнуть за край яйцо, Красного и Синего. Во всех трёх случаях уровень перезапускается с контрольной точки; камера и HUD возвращаются в корректное состояние.

### 35. Добавить кнопку ручного перезапуска

Сделать кнопку паузы и действие «Перезапустить с контрольной точки». При перезапуске не перезагружать всю страницу.

**Тест:** изменить положения обоих игроков, яйца и механизмов, затем выполнить ручной перезапуск. Все объекты возвращаются к состоянию контрольной точки, а игра продолжает работать без ошибки в консоли.

## Этап 7. Механизмы уровня

### 36. Создать формат данных уровня

Описать уровень в одном JSON-файле: границы, платформы, наклоны, шипы, стартовые позиции, кнопки, двери, рычаг, подъёмник, контрольная точка и гнездо. Не хранить координаты уровня в разрозненных модулях.

**Тест:** изменить в JSON положение одной платформы и перезапустить игру. Только эта платформа меняет положение на сцене и в физике.

### 37. Создать красную и синюю кнопки

Кнопки должны срабатывать от игрока своего цвета или от яйца. Каждая имеет наглядную неоновую подсветку состояния «не нажата» и «нажата».

**Тест:** Красный активирует красную кнопку, но не синюю; Синий активирует синюю, но не красную; яйцо активирует обе кнопки.

### 38. Создать дверь и связь с кнопками

Добавить закрытую дверь, которая открывается только пока активна заданная кнопка или пара кнопок. После отпускания последней нужной кнопки дверь ждёт 0,5 секунды, затем закрывается. Она должна иметь твёрдый коллайдер в закрытом состоянии и не блокировать проход в открытом.

**Тест:** попытаться пройти через закрытую дверь — пройти нельзя. Активировать нужную кнопку и провести игрока через открывшийся проём — пройти можно. Отпустить кнопку: дверь начинает закрываться не раньше чем через 0,5 секунды и не закрывается внутри игрока или яйца.

### 39. Создать рычаг

Разместить рычаг, доступный при близком контакте и нажатии клавиши действия. Добавить подсказку взаимодействия, когда игрок находится в радиусе рычага.

**Тест:** вне радиуса подсказка отсутствует и рычаг не переключается. В радиусе правильная клавиша переключает рычаг ровно один раз и меняет его визуальное положение.

### 40. Создать выдвижной мост

Связать рычаг с платформой-мостом. При переключении рычага мост должен плавно выдвигаться на заданную позицию и становиться твёрдой опорой.

**Тест:** до переключения игрок и яйцо не могут пересечь пропасть. После полного выдвижения моста оба могут безопасно пройти по нему.

### 41. Создать цепной подъёмник

Сделать платформу-подъёмник на цепях, которая движется строго между нижней и верхней точками. Активация должна требовать рычага или кнопки, указанной в данных уровня.

**Тест:** загрузить на подъёмник яйцо и одного игрока, активировать механизм и доехать до верхней точки. Ни яйцо, ни игрок не проваливаются сквозь платформу и не соскальзывают без причины.

### 42. Добавить механизм блокировки подъёмника

Не позволять подъёмнику начать движение, если яйцо не находится в безопасной зоне платформы. Показать короткую текстовую подсказку о необходимости загрузить яйцо.

**Тест:** активировать подъёмник без яйца — он не движется и показывает подсказку. Поместить яйцо в центр платформы и повторить активацию — подъёмник движется.

## Этап 8. Собрать один завершённый уровень

### Утверждённый блокинг «Зелёного храма»

Уровень имеет примерно 80 единиц в длину и 30 единиц в высоту. Маршрут идёт слева направо с постепенным подъёмом. На этапе блокинга использовать серые кубы для геометрии, ярко-красные объекты для шипов и неоновые красные/синие объекты для интерактивных элементов. Временно включить debug-отрисовку коллайдеров Rapier, чтобы каждый визуальный объект совпадал с физической границей.

| Зона | Геометрия | Логика прохождения |
|---|---|---|
| 1. Старт | Площадка 10 ед., спуск 10° длиной 8 ед., яма с шипами длиной 4 ед. и глубиной 2 ед., над ней деревянный мост | Игроки толкают и тормозят яйцо перед мостом. При въезде на мост быстрее 7,0 ед/с мост опасно качается и показывает трещины. |
| 2. Нижний коридор | Большая кнопка шириной 2 ед.; через 5 ед. — Дверь №1; за ней — Рычаг №1 | Яйцо удерживает кнопку, открывая Дверь №1. Один игрок проходит и включает Рычаг №1, который фиксирует дверь открытой навсегда. |
| 3. Центральный зал | Пропасть длиной 15 ед.; красная кнопка на возвышении 2 ед.; синяя кнопка на другой стороне; в середине красного моста — углубление с бортиком 0,3 ед. | Красная кнопка выдвигает первую половину моста, синяя — вторую. Яйцо останавливают в углублении, пока Синий добирается до своей кнопки. |
| Контрольная точка | Безопасная площадка сразу после Центрального зала | Сохраняет позиции игроков и яйца, прочность яйца, а также выдвинутые мосты. |
| 4. Подъёмники | Шахта высотой 12 ед.; справа паркур-платформы с шагом 2,5 ед. по высоте; слева цепной подъёмник шириной 4 ед. без бортов | Один игрок поднимается к Рычагу №2, другой грузит яйцо и остаётся с ним на подъёмнике. Пока рычаг удерживают, подъёмник едет вверх; при отпускании медленно опускается. |

На всех открытых краях пропастей добавить бортики высотой 0,5 ед. Яйцо радиусом примерно 0,6 ед. не должно случайно укатываться через бортик, но может пересечь его при намеренном сильном разгоне.

### 43. Создать стартовую секцию

Разместить Красного, Синего и яйцо на стартовой площадке длиной 10 ед., затем создать спуск 10° длиной 8 ед. и яму с шипами длиной 4 ед. Над ямой разместить деревянный мост. При скорости яйца выше 7,0 ед/с мост должен опасно качаться и показывать трещины, но не разрушаться в базовой версии. Использовать эту секцию, чтобы игроки поняли толкание и торможение яйца, не показывая текстовый туториал больше одной строки.

**Тест:** два человека, не знакомые с проектом, могут провести яйцо через первый участок после прочтения подсказки управления. Записать, на чём они ошиблись.

### 44. Создать секцию с цветными кнопками

После моста разместить большую нейтральную кнопку шириной 2 ед. и Дверь №1 через 5 ед. За дверью расположить Рычаг №1. Яйцо удерживает кнопку, дверь открывается; Рычаг №1 фиксирует дверь открытой навсегда. Не использовать цветные кнопки в этой зоне.

**Тест:** яйцо открывает Дверь №1, пока находится на кнопке. Один игрок проходит за дверь, включает Рычаг №1, а после снятия яйца с кнопки дверь остаётся открытой.

### 45. Создать секцию с рычагом и мостом

Создать пропасть длиной 15 ед. с двумя секциями выдвижного моста. Красная кнопка доступна только Красному на возвышении 2 ед. и выдвигает первую половину. Синяя кнопка находится на другой стороне и выдвигает вторую половину. В середине первого моста сделать углубление с бортиком высотой 0,3 ед. для безопасной парковки яйца.

**Тест:** Красный удерживает красную кнопку, Синий проводит яйцо к углублению, затем сам перепрыгивает к синей кнопке. После её удержания Красный безопасно проводит яйцо по второй половине моста.

### 46. Создать центральную контрольную точку

Разместить заметный неоново-зелёный маяк после секции с мостом. При активации записывать положение игроков, яйца, прочность яйца и состояние всех пройденных механизмов.

**Тест:** после активации маяка изменить прочность яйца и состояние рычага, затем уничтожить яйцо. После перезапуска сохраняются только данные, которые должны сохраняться на контрольной точке.

### 47. Создать секцию с подъёмником

После контрольной точки создать шахту высотой 12 ед. с паркур-платформами справа через каждые 2,5 ед. и цепным подъёмником шириной 4 ед. слева. Рычаг №2 находится наверху: пока верхний игрок удерживает его, подъёмник движется вверх; при отпускании медленно опускается. Второй игрок грузит яйцо и остаётся рядом с ним на подъёмнике, чтобы оно не скатилось.

**Тест:** один игрок достигает Рычагa №2 по боковым платформам, второй загружает яйцо на подъёмник. При удержании рычага подъёмник доезжает наверх; при отпускании начинает медленно опускаться, а яйцо и игрок остаются на платформе без проваливания.

### 48. Создать финальный склон и гнездо

Сделать наклон 15° длиной 15 ед., заканчивающийся обрывом. Остров с гнездом должен находиться на расстоянии полёта 3 ед. Игроки тормозят яйцо и отпускают его с края при скорости 5–6 ед/с, чтобы оно долетело до гнезда.

**Тест:** яйцо со скоростью 5–6 ед/с попадает в гнездо. Без торможения оно превышает 12 ед/с и пролетает мимо гнезда либо получает урон при столкновении, но не застревает.

## Этап 9. Финиш, птенец и сохранение

### 49. Создать условие финиша

Гнездо должно активировать финиш, когда яйцо находится внутри его границы и его прочность больше 0%. Нахождение обоих игроков в финишной зоне не требуется.

**Тест:** проверить три случая: целое яйцо в гнезде, разбитое яйцо в гнезде и игроки без яйца в гнезде. Финиш срабатывает только для целого яйца.

### 50. Создать сцену вылупления

После финиша остановить физику и управление, подсветить яйцо сине-фиолетовым светом, показать раскрытие скорлупы и появление одного птенца. Сцена должна длиться коротко и иметь возможность пропуска после первого просмотра.

**Тест:** завершить уровень и дождаться сцены. Птенец появляется ровно один раз, управление не активно до конца сцены, а пропуск не ломает переход к экрану результата.

### 51. Создать запись коллекции

Добавить в `localStorage` версионируемую запись коллекции. При первом успешном завершении открыть одного птенца и сохранить лучшее время и наивысшую прочность яйца для этого уровня.

**Тест:** завершить уровень, перезагрузить страницу и открыть коллекцию. Птенец, лучшее время и лучший процент прочности остаются сохранёнными.

### 52. Создать минимальный экран коллекции

Добавить в главное меню раздел «Коллекция птенцов». Для MVP показать открытую карточку первого птенца и силуэт закрытого будущего птенца. Не добавлять выбор персонажей или бонусы.

**Тест:** до первого прохождения виден только закрытый силуэт. После успешного прохождения карточка птенца открыта, имеет имя и название уровня происхождения.

### 53. Добавить экран результата

После сцены вылупления показать время, текущую прочность яйца, лучший результат и кнопки «Пройти ещё раз» и «В меню».

**Тест:** завершить уровень дважды с разными результатами. Экран показывает текущий результат и корректно обновляет лучший результат только при улучшении.

## Этап 10. Завершение и проверка базовой версии

### 54. Добавить меню паузы и главное меню

Сделать минимальное главное меню с кнопками «Начать игру», «Коллекция» и «Управление». В паузе показать «Продолжить», «Перезапуск с контрольной точки» и «В главное меню».

**Тест:** открыть и закрыть паузу во время движения яйца. Во время паузы физика и таймер не обновляются; после продолжения игра продолжается с того же состояния.

### 55. Добавить звуковую обратную связь

Добавить минимальные звуки: шаг, толчок яйца, удар, нажатие кнопки, движение подъёмника, треск яйца, финиш и вылупление. Добавить общий регулятор громкости в настройках.

**Тест:** выполнить по одному действию каждого типа. Срабатывает только подходящий звук, а изменение громкости влияет на все звуки и сохраняется после перезагрузки страницы.

### 56. Проверить читаемость интерфейса

Проверить HUD, подсказки и кнопки в актуальных стабильных Chrome и Edge на ПК, на экранах 1280×720 и 1920×1080. Текст должен быть читаемым, а шкала прочности — не перекрываться сценой или меню.

**Тест:** сделать скриншоты в обоих браузерах и обоих разрешениях. Все обязательные элементы интерфейса полностью видны и не обрезаны; на современном ноутбуке игра удерживает 60 FPS в обычном прохождении.

### 57. Провести полный функциональный прогон

Пройти игру от главного меню до экрана результата вдвоём без инструментов отладки. Во время прогона использовать все обязательные механики: толкание, торможение, шипы, кнопки, дверь, рычаг, мост, подъёмник, контрольную точку, финиш и вылупление.

**Тест:** полный прогон завершается без ошибки в консоли, без перезагрузки страницы и без ситуации, из которой игроки не могут восстановиться через контрольную точку.

### 58. Провести короткий плейтест

Дать двум новым игрокам пройти уровень без устных объяснений, кроме экрана управления. Наблюдать, понимают ли они, где толкать яйцо, как взаимодействовать с механизмами и почему яйцо получает урон.

**Тест:** записать минимум три наблюдения. Базовая версия считается готовой к следующему этапу, если игроки самостоятельно доходят до контрольной точки и понимают назначение всех основных объектов.

### 59. Проверить production-сборку

Собрать игру для публикации и запустить именно production-версию через статический сервер. Проверить загрузку ассетов, сохранение коллекции и работу перезапуска.

**Тест:** production-версия открывается в чистом профиле браузера, проходит полный функциональный прогон и не показывает ошибок загрузки ресурсов.

### 60. Зафиксировать базовую версию

Сохранить список пройденных тестов, известные ограничения и короткое описание следующего этапа. Следующим этапом может быть либо полировка уровней, либо онлайн-режим, но он не должен изменять правила базовой локальной игры без отдельного решения.

**Тест:** другой разработчик может открыть репозиторий, прочитать этот план и журнал тестов, запустить базовую версию и повторить полный прогон без дополнительных пояснений.
